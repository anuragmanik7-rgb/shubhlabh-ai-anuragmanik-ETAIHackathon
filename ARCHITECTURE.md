# ShubhLabh AI architecture (formerly PromoPilot)

**One orchestrator, deterministic tools, code-certified money, a person in the lead.**
Accenture's terms are used only where code exists: the *orchestrator* is `agent.py`; the *utility agents* are
the tools; the *Human Agent* is the approval and ask-human gate.

## Flow (swimlanes)

```
Category manager      Model (gpt-6-luna / gpt-6.1-sol)        Deterministic code                         Retail sandbox
----------------      --------------------------------        ------------------                         --------------
writes brief  ──────▶ compile_instruction (typed JSON) ─────▶ clamp to HQ policy, read-back ──▶ manager confirms
drops evidence ─────▶ read A (vision, strict JSON)      ─┐    OCR + parser (read C), quarantine, redact
                      read B (other model, doubtful)    ─┴──▶ agreement + location + quality → confidence
                                                              ≥0.90 auto-accept, else review queue ──▶ manager confirms
                      orchestrator picks next tool ◀────────▶ inspect · refresh feeds · forecast · relationships
                      (function calling, `why` logged)        candidates (make_candidate + certificate)
                      submit_strategies (proposals) ───────▶  priced by the same code, certified or rejected
                                                              CP-SAT solve (hint → prune → split → fallback)
                      explain_infeasibility ◀───────────────  relaxation probing (smallest fixes)
                      ask_human ───────────────▶ answers ───▶ resume
                                                              simulate 4 portfolios (selection seed)
                      select_portfolio ─────────────────────▶ eligible? lock; report on separate seed
                                                              finish: validate + certificate per offer
approves (tier, reason, senior sign-off) ◀────────────────── approval tier by liability/depth
                                                              execute ─────────────────────────────────▶ reserve stock + budget
live events ────────▶ triage note/context (may escalate) ──▶ impact + floor (stock/budget hard)          redemptions
                                                              adjust inside envelope / replan + diff ──▶ pause, revise
                      explanations / copy / what-if ───────▶ number check, dark-pattern lint
```

## Decision points and autonomy gates
| Gate | Who decides | Rule |
| --- | --- | --- |
| Which tool next | Model (agent policy) | Only registered tools; strict schemas; preconditions enforced by code; errors returned as observations |
| Constraints from words | Model proposes, code applies | Clamped to HQ policy (never weaker); read-back generated by code |
| Evidence field accepted | Code | Two independent reads agree and value located on the source, or a person confirms |
| Offer exists | Code | `make_candidate` pricing + `validate_candidate` + certificate |
| Portfolio choice | Model (agent) / rule (rules) | Only eligible portfolios; reporting scenarios withheld until locked |
| Publication | Code | `validate_plan` + every certificate passes |
| Approval | Person | Tier: manager; senior above ₹15,000 worst-case or ≥20% depth; reason recorded; bound to revision + snapshot |
| Live event action | Code floor + model | Model may escalate; may downgrade only soft signals to *alert*; `adjust` only inside envelope and ≤ ₹2,000 impact |

## Models
| Purpose | Model | Typical latency | Cost (per 1M in/out) | Fallback |
| --- | --- | --- | --- | --- |
| Orchestrator, compiler, triage, explanations, copy, matching pick | `gpt-6-luna` | 1–4 s per call | $0.10 / $0.50 | Rules policy / offline parser / templates |
| Second read of doubtful evidence fields | `gpt-6.1-sol` (different model) | 2–6 s | $2 / $10 | Field stays in the review queue |
| OCR (read C) | RapidOCR (local ONNX) | ~1.5 s per image | free | Model read only (confidence capped at 0.55) |
Cost, tokens and latency are logged per call and summed per plan (`agent_run.cost_usd`). Daily cap enforced before every call.

## Tool risk ratings
| Tool | Effect | Risk | Control |
| --- | --- | --- | --- |
| inspect_inputs, forecast_demand, analyze_relationships, simulate_compare | read-only | low | — |
| generate_candidates, submit_strategies, optimize_plan, use_fallback_plan | proposes offers | medium | code pricing, certificates, validation |
| compile_instruction | changes the brief | medium | clamp to policy, read-back, logged diff |
| refresh_inventory_feed, refresh_competitor_prices | updates data timestamps / adds observations | medium | feed data only, versioned, no quantities invented |
| select_portfolio, finish | publishes for approval | high | eligibility, validation, approval gate |
| ask_human | pauses | low | — |
| execute (UI/API only, never a model tool) | reserves stock and budget | high | approval required, idempotent |

## Failure modes
| Failure | Detection | Response |
| --- | --- | --- |
| Solver time limit (UNKNOWN) | status | hint → prune → split by city → labelled greedy fallback; still validated |
| Infeasible brief | status INFEASIBLE | relaxation probing; ask the manager; nothing relaxed automatically |
| Model timeout / error / budget cap | AppError code | continue with rules policy from last completed step; run labelled `degraded` |
| Model picks wrong order / bad arguments | precondition / schema | error observation back to the model; it recovers (tested) |
| Unreadable or doubtful evidence | low agreement / quality | review queue; nothing reaches planning until confirmed |
| Prompt injection in evidence or brief | instruction patterns | quarantined before any model sees it; extractor is tool-less |
| Stale inventory / competitor feed | age vs policy | agent refreshes or excludes; validation blocks stale publication |
| Duplicate live event | event_id | first result returned; no second effect |
| Model text with invented numbers | number check | one retry with feedback, then template text (labelled) |
| Copy with dark patterns | lint | one retry with feedback, then template copy (labelled) |
| Process restart mid-run | run record | run marked failed or resumed as a fresh run with the human answer |
